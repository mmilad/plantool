Scope: CLI, API, local web UI (`heist serve`). No MCP, no milestones entity, no hosted sync.

## Problem

Tickets answer **what** and **how it decomposes**; `blocks` and `next` answer **what can run now**. They do not give a durable, browsable view of:

1. **Open + done work together** — context for agents and humans (“what did we already ship under this feature?”).
2. **Completion order over months** — scrollable history (e.g. one year) of what was implemented, not only Git log archaeology.
3. **Blockers across the tree** — who waits on whom, without opening every ticket.

`heist tree` is preorder hierarchy with rollup `blocked` but no filters, no blocker columns, and no completion timeline. The web UI has List/Board/Overview but no dedicated **Roadmap** mode.

## Goals

1. **One canonical model**, multiple projections: **Structure** (tree), **Timeline** (completion order), **Dependencies** (blocker graph) — same tickets, different views.
2. **Include done and cancelled** by default in Structure; Timeline focuses on done (with filters).
3. **Agent-parity**: anything the UI shows must be available as CLI/API with `--format json`.
4. **Long-horizon browsing**: paginated/virtualized lists suitable for hundreds of done tickets over 12+ months.
5. **Reliable completion timestamps** for history (`completedAt`), not `updatedAt` alone.

## Non-goals (this plan)

- Milestones / release phases as first-class entities.
- Execution queue file and drag-and-drop ordering (follow-up; may link here later).
- Force-directed graph for parent hierarchy (parents stay a tree).
- Cross-project roadmap (workspace already lists projects separately).

## Users

| User | Needs |
|------|--------|
| Coding agent | JSON tree with `ready`, `blockedBy`; timeline to find “when X shipped”; deep links `?view=roadmap&ticket=KEY`. |
| Maintainer | Year scroll of outcomes; see open work in structural context. |
| Either | Search/filter within roadmap; jump ticket detail (same as List). |

## Concepts

| View | Question | Layout |
|------|----------|--------|
| **Structure** | Where does work live? What is open vs done in each branch? | Indented tree (default); optional flat outline export. |
| **Timeline** | What was completed, in what order? | Linear, grouped by month (sticky headers). |
| **Dependencies** | What blocks what across branches? | Graph or edge list (v2); not mixed into tree layout. |

**Onboard note**: Roadmap is visualization only initially — no new workflow requirement until optional queue lands.

## Data model

### `completedAt` (and optional `completedBy`)

- Set when a ticket first transitions to `status: done` via `finish` / `done` / API (same path as today).
- **Do not overwrite** on later ticket edits; only clear on reopen (`todo` / `in_progress` with explicit reopen policy).
- **Migration**: existing done tickets — backfill `completedAt` from `updatedAt` once (document in `implementation-decisions.md`); optional `completedAt` missing → fallback in timeline with warning in validate.
- Cancelled tickets remain visible in Structure and are excluded from Timeline until a separate cancellation timestamp is defined.

### Tree row enrichment (computed, not stored)

Per ticket in structure API:

- `ready` (boolean), `readyReasons` (string[])
- `blockedBy`: `{ id, key?, title, via: 'blocks' | 'provider' }[]`
- `blocks`: outgoing blockers (open targets) — optional, for planning
- Keep existing `depth`, `rollup`, `childCount`

### Timeline row

- `id`, `key`, `title`, `kind`, `status`
- `completedAt`, `completedBy?`
- `parentKey?`, `parentTitle?` (breadcrumb)
- `outcome.summary?`, `outcome.changedFiles?` (short, bounded)

## CLI

### Extend `heist tree`

New flags (names negotiable):

| Flag | Purpose |
|------|---------|
| `--hide STATUS,...` | e.g. hide nothing by default; `--hide cancelled` common |
| `--status STATUS,...` | include only these |
| `--ready` | only ready tickets (still show ancestors? **policy: show ancestor chain stub**) |
| `--blocked` | only not-ready due to blockers |
| `--kind KIND,...` | filter |
| `--fields row\|full\|plan` | `plan` = navigation subset + blockers |
| Existing `--max-depth`, `--limit`, `--offset`, `--format json` |

Human text: optional `--verbose` shows `← blocked by KEY`.

### New `heist timeline`

```
heist timeline [--since ISO] [--until ISO] [--status done]
               [--kind ...] [--limit N] [--offset N] [--format json]
```

- Sort: `completedAt` ascending (implementation order) or `--order desc` for “newest first”.
- JSON: `{ items, total, nextOffset }`.

### New `heist deps` (phase 4)

```
heist deps [--root ID] [--format json]
```

- Nodes: tickets (optionally collapse done subtrees).
- Edges: `blocks` + provider edges from code plan (same as `workGraph`).
- Output: edge list in v2.1; simple SVG/HTML only in UI, not CLI requirement.

## API (`heist serve`)

| Endpoint | Purpose |
|----------|---------|
| `GET /api/roadmap/structure` | Same as enriched tree; query = filters above |
| `GET /api/roadmap/timeline` | Paginated timeline rows |
| `GET /api/roadmap/deps` | Bounded dependency nodes and edges |

Bump UI `?view=roadmap&mode=structure|timeline|deps&ticket=`.

## Web UI: Roadmap page

### Navigation

- Sidebar entry **Roadmap** (alongside Overview, List, Board, …).
- Segmented control: **Structure** | **Timeline** | **Dependencies**.

### Structure mode

- Reuse tree interaction (expand/collapse, keyboard); show **done** muted (checkmark, lower contrast), **open** normal, **blocked** badge, **in_progress** + assignee.
- Filters: text, status (multi), kind, “only blocked”, time range N/A.
- Default: **show all statuses** including done (user requirement).
- Optional toggle: **Collapse done subtrees** (hide leaves, keep parent stub) — not default.
- Optional toggle: **Outline** — flat preorder with `KEY` + indent spaces (agent copy-friendly).

### Timeline mode

- Virtual scroll / “Load older” with month group headers.
- Range: Last 30d | 90d | 1y | All.
- Row click → ticket detail (shared with List).
- Show `outcome.summary` one line; expand in detail panel.

### Dependencies mode (phase 4)

- Read-only graph for current filter scope OR selected root.
- Fallback on small screens: table **Blocked ticket | Blocked by | Type**.

### Agent alignment

- Document in `heist agent onboard` / guide: use `tree --fields plan`, `timeline`, Roadmap URL modes — not a full re-onboard.
- `heist context` may include `completedAt` of recent siblings under parent (optional, small).

## Acceptance criteria (release slice = phase 1–3)

1. A done ticket has stable `completedAt`; timeline order matches known finish order in tests.
2. `heist tree --fields plan --format json` returns `blockedBy` and `ready` for blocked and ready tickets.
3. Roadmap Structure shows open and done; done visually distinct; 500+ tickets usable with paging.
4. Roadmap Timeline scrolls 12 months of data via pagination without loading all DOM nodes.
5. CLI and API responses share the same row shape (modulo `fields`).
6. No regression: existing `tree` default output unchanged without new flags.
