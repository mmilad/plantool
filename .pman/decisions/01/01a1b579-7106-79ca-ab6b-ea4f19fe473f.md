Tickets only have the kinds task, feature and bug. Code structure (module, service, class, method, function, ui-component) is not modelled as ticket subtypes but as centrally maintained components, contracts and types. A ticket optionally carries a code plan (implements, consumes with requires, changes). Plain tasks need no code plan. Details: docs/implementation-decisions.md.
