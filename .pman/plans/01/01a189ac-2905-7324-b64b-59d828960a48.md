## Review cadence
In every UI planning round: look at the UI, check existing UI tickets and ownership, add observations to docs/ui-review.md and make required plan changes through pman. After implementation rounds, review the visible UI again and refine tickets and plan from the evidence.

## Initial findings
The original UI was a simple two-column page. Search, the full ticket tree, planning documents and the ticket form shared the narrow sidebar; the main area stayed empty until a ticket was selected. Ticket actions and statuses were plain inline elements. There was no icon system.

## Work packages
The tickets linked under "Design and build a simple planning UI for Planus Manus" (01a189a9-429e-7fb4-9d2c-8db0221f8942) are the executable work packages. The review task stays a child of this UI programme and is used for iterative re-planning.

## Ownership
All UI work stays under the parent UI ticket. This planning document links the programme, its work packages and the review task. Goal and plan reference the related ticket IDs; pman supports cross-ticket relationships only between tickets.
